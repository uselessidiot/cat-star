# 인증 API 계약 (Codex UI 연동용)

이 문서는 `고양이의 별`에 **간단한 이메일/비밀번호 로그인 UI**를 붙이는 Codex(프론트 담당)를 위한 계약서입니다.

인증 로직·세션·데이터 연동은 백엔드(Claude Code)가 API로 이미 구현했습니다. **프론트는 Supabase를 직접 호출하지 않고, 아래 4개 엔드포인트에 요청만 보내면 됩니다.**

가장 중요한 원칙은 [BACKEND_HANDOFF.md](../BACKEND_HANDOFF.md)와 같습니다 — 밤하늘의 감성, 별 배치, 고양이 이동감을 깨지 않는 선에서 로그인 UI를 얹습니다.

---

## 왜 필요한가 (UX 의도)

지금은 로그인이 없어서, 각 사용자의 기억별이 **그 브라우저 하나에만** 묶여 있습니다. 쿠키를 지우거나 다른 기기로 오면 자기 별을 잃어버립니다.

이 API는 그 한계를 풉니다:

- **처음 방문자는 여전히 가입 없이 바로 시작**합니다 (익명). 이 감성은 유지합니다.
- 원할 때 **이메일/비밀번호를 붙여 "내 별 저장"** 하면, 그 순간부터 계정에 데이터가 묶입니다.
- 다른 기기에서 **로그인하면 자기 별이 그대로 돌아옵니다.**

핵심 마법: 익명 계정에 이메일을 붙이면 내부 사용자 id가 **그대로 유지**되어, 이미 만든 별·사진이 **자동으로 계정에 딸려옵니다.** 프론트가 데이터를 옮기는 작업은 필요 없습니다.

---

## 사전 조건 (Supabase 설정)

Supabase 대시보드에서 **Authentication → Providers → Email → "Confirm email" 을 꺼야** 합니다. 켜져 있으면 확인 메일을 받아야만 로그인이 되어, 가입/로그인이 막힙니다. (베타 기준. 정식 오픈 때 다시 검토)

---

## 엔드포인트

모든 요청/응답은 JSON입니다. 세션은 쿠키로 자동 관리되므로, 프론트는 토큰을 저장할 필요가 없습니다. `fetch` 기본값으로 같은 오리진 쿠키가 함께 전송됩니다.

### 1. `GET /api/auth/session`

현재 로그인 상태를 조회합니다. UI가 "로그인/로그아웃 버튼 중 무엇을 보일지" 결정할 때 사용합니다.

응답 `200`:

```json
{ "authenticated": true, "isAnonymous": false, "email": "user@example.com" }
```

- `isAnonymous: true` → 아직 익명 (가입/로그인 버튼 노출)
- `authenticated: true` → 이메일 계정으로 로그인됨 (이메일 표시 + 로그아웃 버튼)
- `email` 은 익명일 때 `""` 또는 `null` 일 수 있음

### 2. `POST /api/auth/register`

지금의 익명 세션을 **이메일 계정으로 승격**합니다. 기존 별·사진은 그대로 유지됩니다.

요청:

```json
{ "email": "user@example.com", "password": "8자이상비밀번호" }
```

응답:

- `200` → `{ "ok": true, "email": "user@example.com" }`
- `400` → `{ "error": "사람이 읽을 한국어 메시지" }` (이메일 형식 오류, 비번 8자 미만, 이미 가입된 이메일 등)
- `409` → `{ "error": "이미 로그인되어 있어요." }` (이미 계정 로그인 상태에서 또 가입 시도)

### 3. `POST /api/auth/login`

기존 계정으로 로그인합니다. **다른 기기/브라우저에서 자기 데이터를 되찾을 때** 사용합니다.

요청:

```json
{ "email": "user@example.com", "password": "비밀번호" }
```

응답:

- `200` → `{ "ok": true, "email": "user@example.com" }`
- `400` → `{ "error": "..." }` (형식 오류)
- `401` → `{ "error": "이메일 또는 비밀번호가 맞지 않아요." }`

### 4. `POST /api/auth/logout`

로그아웃합니다. 다음 요청부터 다시 익명 상태가 됩니다.

- `200` → `{ "ok": true }`

## UI가 처리해야 할 흐름

### 화면 상태 (마운트 시 `GET /api/auth/session` 로 판별)

| 상태 | 보여줄 것 |
|---|---|
| `isAnonymous: true` | "내 별 저장 / 로그인" 진입점 |
| `authenticated: true` | 이메일(또는 "로그인됨") + "로그아웃" |

### 가입/로그인 폼

- 이메일 + 비밀번호 두 칸. 비밀번호는 **최소 8자** (서버도 검증하지만, 프론트에서 미리 막아주면 UX가 좋음)
- "처음이신가요? → 가입 / 이미 계정이 있어요 → 로그인" 두 모드 토글 정도면 충분
- 서버가 돌려주는 `error` 문자열은 **이미 한국어 사용자 메시지**이므로 그대로 화면에 띄우면 됩니다

### ⚠️ 로그인/로그아웃 후 데이터 새로고침 (중요)

- **`register`(승격)**: 같은 id라 데이터가 그대로 → 별도 새로고침 불필요 (상태 표시만 갱신)
- **`login` / `logout`**: 사용자 정체성이 **바뀌므로**, 밤하늘의 별 목록을 **다시 불러와야** 합니다. 성공 후 아래 이벤트를 발생시키면 기존 로직(`SkyScene`/`MemoryAlbum`이 이 이벤트로 `getApiMemories()` 재호출)이 자동으로 다시 로드합니다:

```js
window.dispatchEvent(new CustomEvent('cat-star-memory-store-changed'));
```

(이벤트 상수는 `lib/memory-store.ts`의 `MEMORY_STORE_CHANGED` 입니다. 간단하게는 `location.reload()` 로도 됩니다.)

## 알아둘 점

- **익명으로 만든 별 vs 로그인 계정의 별**: 익명 상태에서 별을 만든 뒤 *기존 다른 계정으로 로그인*하면, 화면엔 그 계정의 별이 나오고 익명으로 만든 별은 사라진 것처럼 보입니다(그 익명 id에 남아 있을 뿐 접근 불가). "지금 만든 별을 지키려면 로그인 말고 **가입(register)**을 하세요"를 안내하면 혼란을 줄일 수 있습니다.
- **비밀번호 재설정(찾기)**: 메일 발송이 필요해 베타 범위에서 제외했습니다. 필요해지면 백엔드에 요청하세요.
- 프론트는 여전히 Supabase 키·클라이언트를 다룰 필요가 없습니다. 위 4개 엔드포인트만 쓰면 됩니다.
